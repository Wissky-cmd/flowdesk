# FlowDesk 完善度复查 · 2026-10-05

本轮发现并修复了任务恢复、并发清理、分页和错误反馈中的实际缺陷。现有验证范围内未发现尚未修复的阻塞性问题；这不代表所有部署环境、容量或无障碍能力均已验收。

## 已修复

| 问题 | 修复与验证 |
| --- | --- |
| 人工重试绕过每人 5 个待处理任务上限 | 创建与重试共用成员行锁和数量检查。真实 PostgreSQL 两个并发重试争抢最后一个名额，恰好一个成功、一个 429；失败请求不改变轮次。 |
| 到期任务依赖后台扫描才能显示过期、释放配额及重试 | 查询按到期时间显示状态；配额排除到期任务；重试允许尚未被扫描的过期记录。覆盖排队及成功两种旧状态，并保持下载返回 410。GET 不写数据库。 |
| 文件清理可能删除重试后刚生成的同名 CSV | 清理持有与 Worker 发布相同的任务行锁，覆盖状态检查和删除。暂停删除时，另一 PostgreSQL 连接使用 NOWAIT 获取锁失败；清理结束后重试、生成、下载成功。 |
| 生成过程中到期的导出仍可发布 | 发布前复验任务到期时间。故障注入验证跨到期后不留下 CSV 或临时文件。 |
| 任务列表、活动列表翻到空页后总数错误归零 | 空页补查当前权限范围内总数，验证越界页、其他用户隔离及无权工单 404。 |
| 任务页刷新、翻页或新建后的加载请求互相覆盖或被忽略 | 用请求序号仅接收最新结果；浏览器延迟旧响应后切到下一页，保持正确页码和记录。 |
| 重试失败信息藏在弹窗后面 | 错误显示在弹窗内部并保留原因；重新打开清空旧草稿与错误；提交期间防止关闭。浏览器验证 429 提示和 320px 布局。 |
| CSV 查询加载了不使用的工单正文 | 只选择导出的 7 个字段，保留权限过滤、10,000 条上限与公式注入防护；现有真实导出内容回归通过。没有将此改动宣称为已测量的性能提升。 |

## 仍需完善或验收

1. **真实任务服务与登录限流**：本机未配置真实 Redis，未运行自动 Worker；新导出仍会排队。本机 RATE_LIMIT_ENABLED=false。需要在目标环境验证 Redis Lua 限流、Celery 实际投递/消费/重启恢复；本轮数据库测试不替代这项验收。
2. **部署与持续集成**：Linux、Docker Compose/Nginx、HTTPS 与远程 Actions 尚无运行记录。本机没有 Docker、WSL，仓库无远程。相关交付文件已存在，但不能宣称已部署通过。
3. **规模与体验验证**：尚未做大数据量、长时间运行、吞吐与并发容量测量；完整键盘/读屏审计和跨浏览器覆盖仍需补充。现有小数据 EXPLAIN 与 Chromium 测试不构成这些结论。
4. **产品扩展项**：集成令牌列表尚无分页和活跃数量上限；任务记录界面仅展示最近 100 条且为打开时快照。当前可以使用，但大量长期记录场景需要补全浏览入口和容量策略。
5. **存储取舍**：附件目前每单最多 10 个、每个 5 MiB，存 PostgreSQL；增长到较大体量时应评估对象存储、数据保留和归档策略。当前实现有明确限制，并非无限容量。

上线前优先完成前两项，再用目标数据规模和使用设备完成第三项。更多环境说明见 [deployment.md](deployment.md)。
